## 一、拦截现象与判定机制

### 1. 页面固定文案

被拒时豆包返回：

> 生成的视频可能涉及版权限制，请更换输入内容后重试

后端 `[reject]` 命中拒绝词「版权限制」，标记 `REJECTED`，停止等待、不再确认。

### 1.1 两类失败文案，不可混为一谈

| 页面文案 | 性质 | 处置 |
| --- | --- | --- |
| 生成的视频可能涉及版权限制，请更换输入内容后重试 | 风控 / 敏感 / 版权拦截（文本或图片） | 改词 / 撤图二分 |
| 视频生成失败，生成额度未扣除（错误码 `710082025`） | 服务端渲染 / 生成临时异常，非风控 | 直接重试，换账号或稍后再试，不改词 |

> 后端 `REJECT_HINTS` 词表同时收录了「版权限制」「生成失败」等词，目前统一标成 `REJECTED`，两类在日志里看起来一样，需按页面文案区分（见未决事项第 2 条）。

### 1.2 账号 / IP 级行为风控（2026-11-15 晚定性）

> 与「单条提示词 / 图片被拦」不同：本轮判断为**同一 IP 下多账号、高频天天生成视频，被平台做 IP（含账号关联）维度标记**，模型对这些号直接拒绝出片；不是某一条台词或某张图违规。

**IP 封锁反证（已验证）**：本机直连时各号普遍不受理；**切换手机热点（出口 IP 变更）后即可正常生成**。说明当前封禁对象是出口 IP，账号本身未被永久封。需进一步区分：换 IP 后若老号恢复 → 纯 IP 标记；若老号仍不行 → 账号也被连带标记。

* 账号池 8 个号：`account_1/2/4/5/6`（free）今日各用满 2 条（cap=0）；`account_3`（会员）额度耗尽（used 15939 / total 16100）；只剩新号 `account_7`（dongxiangyu4mm）、`account_8`（dongxiangyu5bb）available。
* 新号登录态正常：`logged_in=true`、`last_check.ok=true`、cookies 含 `sessionid / sessionid_ss / sid_tt / uid_tt / passport_auth_status` 等核心凭证、今日用量 0；后端按 free 每日 2 条判定 available、cap=2，不会被额度窗口缺失排除。

**与单条内容风控的区分：**

| 维度 | 单条内容风控 | 账号 / IP 行为风控（本节） |
| --- | --- | --- |
| 触发对象 | 某条提示词 / 某张参考图 | 账号、IP、行为频率与多账号关联 |
| 表现 | 特定分镜被拦，换干净分镜可能通过 | 跨分镜、跨账号普遍不出片 |
| 页面文案 | 命中版权 / 违规 / 敏感字样 | 常无明确违规文案，登录态正常但服务端不受理 |
| 处置 | 改词 / 撤图二分 | 降频、错峰、轮换节奏放慢、分散出口 IP |

**处置口径（记录备查，不主动执行）：**

* **立即可做（不改代码）**：换出口网络（手机热点 / 另一宽带 / 移动网络）即可恢复；降低单 IP 并发与单日总量，拉长生成间隔、错峰；账号轮换放慢，新号先少量试跑养号，不要一上来批量。
* **自动化落地：按账号绑定独立出口代理**。账号记录增加 `proxy`（server / username / password）字段，启动 Chrome 时按账号注入 Playwright `proxy` 参数；`connect_with_cookies` 的 `launch(proxy=…)` 与 `connect_to_profile` 的 `launch_persistent_context(proxy=…)` 两个注入点。每个账号固定走一个代理出口，不频繁随机跳，避免账号 IP 漂移本身可疑。代理优先住宅 / 移动代理，机房 IP 易被批量标记。

**代理落地状态（2026-11-15 晚，代码留工作区未提交）：**

* 后端 `core/doubao_account_pool.py`：`allocate_tasks` / `allocate_parallel` 分配字典带 `proxy`；`public_view` / `get_account_status` 对外透出 `proxy`。

### 2. 官方错误码分类（火山方舟错误码文档）

前端把多类拦截收敛成同一句 "版权限制" 文案，**页面上看不出是文本还是图片触发**。后端对应的错误类型：



| 错误码 Type                                                | 含义                 | 触发对象       |
| ------------------------------------------------------- | ------------------ | ---------- |
| `InputTextSensitiveContentDetected.PolicyViolation`     | 输入文本可能涉及版权限制       | 提示词 / 台词文本 |
| `InputImageSensitiveContentDetected.PolicyViolation`    | 输入图片可能涉及版权限制       | 参考图 / 首帧   |
| `InputImageSensitiveContentDetected.PrivacyInformation` | 输入图片包含真人           | 参考图 / 首帧   |
| `InputImageRiskDetection`                               | 输入图片含违反内容安全检测的敏感信息 | 参考图 / 首帧   |

## 五、剪映导出素材不可播（code 256）——2026-11-16 定位并解决

### 5.1 现象

后端直写剪映草稿后，新素材在剪映里黑块 / 无法预览，界面误报「格式不支持」；历史手动导入过的旧素材正常。

### 5.2 根因

剪映按素材绝对路径为**外部文件**建立 macOS 安全作用域书签（app-scope bookmark）。后端命令行写草稿只挂路径字符串、无用户手势授权上下文，新书签创建返回 `NSCocoaErrorDomain 256`（Failed to retrieve app-scope key）→ `HasPermission` 无权限 → `getAVStreamInfo` 进门即失败（costTime=0）→ media missing，UI 误报格式异常。

### 5.3 正解（已落地，任务 #123）

不与外部书签授权硬碰，把素材放进剪映**草稿自有目录** `Resources/`，草稿 json 与 meta 写草稿内绝对路径。剪映对草稿目录内文件不走外部安全书签，直接读盘。

- 后端 `backend/api/video.py` `export_jianying`：建草稿后建 `Resources/`，`shutil.copy2` 拷贝素材，`videos[].path` 与 `draft_materials[].file_Path` 写内部路径；同名冲突加 md5 前缀。
- 实测：新草稿 12 条全内部路径，日志 `256 / no permission / bookmark failed` 计数为 0，`video_add` 与 `checkChildrenFile` 全 success。
- 剪映存盘时会把内部路径规范化为 `##_draftpath_placeholder_<草稿id>_##/Resources/...` 占位符，属正常。

### 5.4 已排除的死路（勿重试）

- **转 H.264/CFR/重编码、重整容器、faststart**：失败片本就 h264/yuv420p/aac、解码零报错；256 发生在进门之前，与编码无关。
- **补草稿 JSON 注册字段、抄 platform 指纹、补封面**：A/B 快照与能播基线对齐，不影响书签授权。
- **伪造 bookmark blob、改 POSIX 权限 / ACL / xattr**：沙盒设计上后端代写不了 app-scope 书签。
- **重启 ScopedBookmarkAgent / 清钥匙串**：本轮实测强杀代理重生后仍稳定 256，未恢复；`codesign` 签名校验通过。这些不是本机该故障的解。

### 5.5 操作注意

- 导出 / 写草稿前先彻底退出剪映（Cmd+Q）；剪映开着时写盘，退出会把内存旧路径回写覆盖 json。
- 素材随草稿打包进 Resources，草稿目录占用 ≈ 素材总大小。
