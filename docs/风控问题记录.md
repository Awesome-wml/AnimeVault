## 一、拦截现象与判定机制

### 1. 页面固定文案

被拒时豆包返回：

> 生成的视频可能涉及版权限制，请更换输入内容后重试

后端 `[reject]` 命中拒绝词「版权限制」，标记 `REJECTED`，停止等待、不再确认。

### 1.1 两类失败文案，不可混为一谈

| 页面文案 | 性质 | 处置 |
| --- | --- | --- |
| 生成的视频可能涉及版权限制，请更换输入内容后重试 | 风控 / 敏感 / 版权拦截（文本或图片） | 改词 / 撤图二分 |
| 视频生成失败，生成额度未扣除（错误码 `710082025`） | 服务端渲染 / 生成临时异常，非风控 | 直接重试，换账号或稍后再试，不改词 |

> 后端 `REJECT_HINTS` 词表同时收录了「版权限制」「生成失败」等词，目前统一标成 `REJECTED`，两类在日志里看起来一样，需按页面文案区分（见未决事项第 2 条）。

### 2. 官方错误码分类（火山方舟错误码文档）

前端把多类拦截收敛成同一句 "版权限制" 文案，**页面上看不出是文本还是图片触发**。后端对应的错误类型：



| 错误码 Type                                                | 含义                 | 触发对象       |
| ------------------------------------------------------- | ------------------ | ---------- |
| `InputTextSensitiveContentDetected.PolicyViolation`     | 输入文本可能涉及版权限制       | 提示词 / 台词文本 |
| `InputImageSensitiveContentDetected.PolicyViolation`    | 输入图片可能涉及版权限制       | 参考图 / 首帧   |
| `InputImageSensitiveContentDetected.PrivacyInformation` | 输入图片包含真人           | 参考图 / 首帧   |
| `InputImageRiskDetection`                               | 输入图片含违反内容安全检测的敏感信息 | 参考图 / 首帧   |

### 3. 已排除的方向（避免重复排查）



* **素材同批复用**：三张角色板（李川 `86122a59…`、楚梦幽 `aa945195…`、赵丙谦 `87872302…`）+ 场景图（`58ce3aa6…`）在成功分镜 shot6 上同样上传并过审，资产图本身不是新增风险。

* **提示词无显性违规项**：全文无知名作品名、品牌名、明星名；台词已逐句复核。

### 4. 排查手段



* 后端日志：`backend/backend.log`，搜 `[reject] 命中拒绝词`、`FAILED_REJECTED`、`生成完成`。

* 留证：`output_videos/chain_body_*.json`（本次拒绝的完整下行 body）。

* 历史对话回读：用对应账号 cookies 打开失败对话 URL，只读提取豆包回复气泡，核对受理流程与最终拦截文案。

* DB：`shots` 集合按 `project_id + shot_no` 回读 `lines / text / video_prompt / prompt / beats / storyboard_prompt`。
